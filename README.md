## Задание 2

### C++

```cpp
int main() {
   int a=1, b=2;
   int c=a++b;
   return 0;  
}
```

Последовательность токенов:

```
int `c` =  `a` `++` `b` ;
```

Ошибка компиляции при разборе a++b в C++ вызвана тем, что лексический анализатор выделяет токены `a`, `++` и `b`. Оператор `++` распознается как унарный постфиксный инкремент для `a`. В результате переменная `b` оказывается изолированной, так как между ней и выражением `a++` отсутствует связующий бинарный оператор.

### Python

```python
a = 1
b = 2
c = a++b
```

Последовательность токенов:

```
c | = | a | + | + | b
```

В языке Python синтаксическая конструкция ++ как единый оператор отсутствует. Интерпретатор распознает этот фрагмент как последовательность из двух самостоятельных операторов сложения +: первый выполняет роль бинарного оператора, а второй — унарного знака плюс. В результате выражение принимает вид:

```python
c = a + (+b)
```

При условных переменных a = 2 и b = 2 результатом операции становится 4, что делает код полностью валидным и исполняемым.

## Задание 3

Программа:

```cpp
int a = 1, b = 2;
int c = a+++b;
```

Программа на C++ успешно компилируется и выполняется. После выполнения значения переменных будут следующими:
- a = 2 (так как сработал инкремент)
- b = 2 (осталось неизменным)
- c = 3 (так как постфиксный инкремент возвращает старое значение a, то есть 1 + 2)

Токенизация строки:

```
int `c` = `a` `++` `+` `b` ;
```

Разбиение можно изменить с помощью пробелов, что поменяет логику:
- c = a + ++b; — программа скомпилируется, но результат изменится: сперва увеличится `b` до 3, а затем `c` станет равно 1 + 3 = 4.
- c = a ++ + b; — логика останется изначальной.
- c = a + + + b; — превратится в сложение `a` с `дважды унарным плюсом b` (результат 3, но `a` не увеличится).

## Задание 5

Программа:

```python
print(*map(sum, zip(
    *[map(int, input().split()) for i in (1, 2, 3)]
)))
```

Ключевые слова: `for, in`.
Идентификаторы: `print, map, sum, zip, int, input, split, i`.
Литералы: `1, 2, 3`.
Оператор: `*`.

Перечень вызываемых функций и их параметры:
- `input()` — без параметров. Читает строку из консоли.
- `split()` — вызывается как метод у строки без параметров. Разрезает строку по пробелам на список строк.
- `int` — используется внутри map как объект-функция для преобразования строк в числа.
- `map(int, ...)` — применяет преобразование к каждому элементу списка.
- `zip(*...)` — принимает распакованный список списков чисел. Группирует элементы по индексам (транспонирует матрицу).
- `sum` — используется в верхнем map для подсчета суммы в каждой сгруппированной строке.
- `print(...)` — выводит итоговый результат в консоль.

### Что делает программа

Программа считывает из консоли матрицу размера `3` строки на `N` столбцов, а затем вычисляет сумму элементов в каждом столбце и выводит эти суммы через пробел.

### Как приходит к результату

Генератор списка считывает 3 строки текста, превращает каждую в список чисел через `map(int, input().split())`. Функция `zip(*...)` берет эти три списка и перегруппирует их так, что в первый кортеж попадают все первые элементы строк, во второй — все вторые (столбцы). Верхний `map(sum, ...)` считает сумму каждого получившегося кортежа-столбца, а `print(*...)` распаковывает их и печатает.

### Пример данных для работы программы
```
1 2 3
10 20 30
100 200 300
```
Результат: 
```111 222 333```

## Задание 6

В C++ есть два вида комментариев: `однострочные //` и `многострочные /* ... */`. Многострочные комментарии нельзя вкладывать друг в друга.

### 1. Строковый литерал

```cpp
cout << "Hello /* Это комментарий */ world";
```

Синтаксически **корректно**

Комбинация символов `/* ... */` заключена в двойные кавычки. Для компилятора это не разметка комментария, а обычные символы внутри текстовой строки.

### 2. Однострочный комментарий

```cpp
// /*
 Это комментарий
*/
```

Синтаксически **ошибочно**

Символы `/*` находятся в строке, начинающейся с `//`, поэтому они полностью игнорируются и не открывают блок комментария. Вторая строка воспринимается как обычный код, а одиночный закрывающий маркер `*/` в третьей строке вызывает синтаксическую ошибку, так как для него нет пары.

### 3. Вложенный многострочный комментарий

```cpp
/* Я комментирую программы /* комментарий */ */
```

Синтаксически **ошибочно**

Стандарт C++ запрещает вложенность блоков `/* ... */`(многострочные). Анализатор закрывает комментарий на первом же встреченном токене `*/`. Из-за этого финальный маркер `*/` оказывается лишним.

### 4. Однострочный комментарий

```cpp
// Я комментирую программы /* комментарий */
```

Синтаксически **корректно**

Знак `//` полностью превращает всю строку до самого конца в комментарий. Что написано после него — системе неважно.

### 5. Многострочный комментарий с `//`

```cpp
/* Я комментирую свои программы
// Это комментарий до конца строки */
*/
```

Синтаксически **ошибочно**

Знак `//` внутри большого комментария не работает. Первые два знака `*/` успешно закрывают комментарий на второй строке. Из-за этого самый последний `*/` на третьей строке оказывается лишним.

## Задание 8

Нужно построить абстрактное синтаксическое дерево для выражения, вычисляющего значение `а` в программе :
```cpp
int main() {
int a,x,y,z;
cin >> x >> y >> z;
a = -x+y*(z-1);
}
```

Само выражение:
```
a = -x+y*(z-1);
```


Сначала приоритет операций:

1. Скобки `(z - 1)`;
2. Унарный минус `-x`;
3. Умножение `y * (z - 1)`;
4. Сложение `-x + ...`;
5. Присваивание результата переменной `a`.

Упрощённое абстрактное синтаксическое дерево:

```
         [ = ]
        /     \
      [ a ]   [ + ]
            /     \
         [ - ]   [ * ]
          /       / \
       [ x ]   [ y ] [ - ]
                      / \
                   [ z ] [ 1 ]

```
